|-------------|----------|--------|

#### 1.3 身份认证

**置信度**：🟡 合理推断

**推断依据**：
- API 文档定义了 401 响应（未认证）
- Mattermost 支持多种认证方式

**认证方式**（🟡 已确认事实，来自开发者文档）：
1. **Cookie + Session**：浏览器环境
2. **Authorization: Bearer <token>**：API token 或 Personal Access Token
3. **MFA Token**：多因素认证

**重要发现**（🔵 已确认事实，来自 PR #35825 测试用例）：
> "cookie auth without X-Requested-With header should be rejected"

**安全机制**：
- 如果使用 Cookie 认证（无 `Authorization` 头）
- 但缺少 `X-Requested-With` 头
- 会被拒绝，返回 **403 Forbidden**
- **目的**：防止 CSRF 攻击

**预期错误场景**：
| HTTP 状态码 | 触发条件 | 置信度 |
|-------------|----------|--------|
| 401 Unauthorized | 无效或过期的认证凭证 | 🔵 已确认 |
| 403 Forbidden | Cookie 认证但缺少 `X-Requested-With` 头 | 🔵 已确认 |

#### 4.3 特殊场景说明

**场景 A：插件取消帖子（🔵 已确认事实）**

这是一个特殊的"错误"：
- 不是真正的错误，而是插件的正常业务决策
- 插件可以在 `MessageWillBePosted` 钩子中决定不允许帖子发布
- 前端处理方式：移除本地帖子（与其他不可逆错误相同）

**场景 B：Town Square 只读（🔵 已确认事实）**

- 系统配置项：`TownSquareIsReadOnly`
- 如果设置为 `true`，普通用户无法在 Town Square 发帖
- 只有管理员可以发帖

- WebSocket 广播可能涉及多个连接

#### 8.2 WebSocket 事件格式（🔵 已确认事实）

**来源**：GitHub Issue #22110

```json
{
    "event": "posted",
    "data": {
        "channel_display_name": "General Discussion",
        "channel_name": "general",
        "channel_type": "O",
        "mentions": "[\"user1\", \"user2\"]",  // ⚠️ JSON 字符串！
        "post": "{\"id\":\"xxx\",\"create_at\":1674132302437,\"message\":\"hello\"}",  // ⚠️ JSON 字符串！
        "sender_name": "@johndoe",
        "set_online": true,
        "team_id": "team123"
    },
    "broadcast": {
        "omit_users": null,
        "user_id": "",
        "channel_id": "channel123",
        "team_id": "team123",
        "connection_id": ""
    },
    "seq": 3
}
```

**重要发现**（🔵 已确认事实）：
- `data.post` 是 **JSON 字符串**，不是 JSON 对象
- `data.mentions` 是 **JSON 字符串**，不是数组
- 客户端需要对这些字段进行**二次 JSON 解析**

#### 8.3 广播范围控制（🟡 合理推断）

基于 `broadcast` 字段推断：

| 字段 | 用途 | 示例值 |
|------|------|--------|
| `channel_id` | 广播到该频道的所有成员 | "channel123" |
| `user_id` | 广播到特定用户（空 = 所有） | ""（所有用户） |
| `omit_users` | 排除这些用户 | null 或 ["user1"] |
| `team_id` | 团队 ID（用于跨频道广播） | "team123" |

#### 8.4 特殊处理：排除发送者（🟡 合理推断）

**推断依据**：
- 发送者已经通过 API 响应知道消息发送成功

| 结论 | 推断依据 |
|------|----------|
| 服务端采用 API → App → Store 三层架构 | Mattermost 官方文档、标准企业架构 |
| 数据库操作在事务中执行 | 数据一致性要求、标准模式 |
| WebSocket 广播在 API 响应之后异步执行 | 性能优化考虑、事件格式证据 |
| 发送者自己不接收 WebSocket 广播 | 已经通过 API 响应知道结果 |
| 权限检查按层次进行（认证 → 频道状态 → 成员身份 → 功能权限） | 错误 ID 分析、标准权限模型 |

### 数据缺口（❌）

| 信息类型 | 缺口原因 | 影响 |
|----------|----------|------|
| API Handler 具体实现 | `server/public/` 目录缺失 | 无法确认路由、参数解析、中间件 |
| App 层业务逻辑细节 | `server/public/` 目录缺失 | 无法确认插件钩子、通知逻辑 |
| Store 层数据库操作 | `server/public/` 目录缺失 | 无法确认 SQL、事务、缓存 |
| WebSocket 广播实现 | `server/public/` 目录缺失 | 无法确认连接管理、集群广播 |

## 建议

### 对于开发者

1. **调试定位**：
   - 前端问题：检查 `webapp/channels/src/packages/mattermost-redux/src/actions/posts.ts`
   - 网络问题：检查 `webapp/platform/client/src/client4.ts`
   - 服务端问题：需要访问 `server/public/` 目录下的代码

2. **错误排查**：
   - 使用 `server_error_id` 定位具体错误类型
   - 参考 `server/i18n/en.json` 中的错误消息

3. **权限问题**：
   - 确认用户是频道成员
   - 确认用户有 `create_post` 权限
   - 检查频道是否被删除或只读
